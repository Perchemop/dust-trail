# Ticket T-010: Implement depth-aware composite (sprite → Frame with z-compare, back-to-front order)

## Objective
Implement the composite step that writes sprites into the frame with depth-aware occlusion, drawing back-to-front by screen depth.

## Target Files
- `apps/dust-trail/src/render/composite.rs` (new)

## Acceptance Criteria
- [ ] Composite function that takes a `Frame`, a `Sprite`, and screen position, writes sprite cells using `set_at_depth`
- [ ] Depth-aware overwrite: nearer depth wins, farther skips (FR-032, AC-016)
- [ ] Objects drawn back-to-front by screen depth (far first, near last) (FR-034)
- [ ] Tree in front of player → tree's cells shown, player's hidden at overlap (FR-033, AC-006)
- [ ] Frame depth buffer reset before first composite (FR-035, AC-017)
- [ ] Out-of-bounds cells skipped gracefully (no panic)
- [ ] Unit tests: depth-aware overwrite, farther-wins skip, clear_depth resets to infinity, out-of-bounds no-op (AC-006, AC-016, AC-017)
- [ ] CI passes: `cargo test --workspace -- render::composite` (headless, no GUI)

## Blocking Dependencies
- T-006 (Sprite type)
- T-009 (Frame depth buffer)

## Notes
- Per NFR-007: `composite.rs` and the GUI layer are the only ones that may depend on domain `Frame`/`Cell`
- This is where the occlusion magic happens — critical for correct visual layering
- Draw ordering: the existing `Game::frame()` already sorts objects back-to-front by screen depth; composite respects that
