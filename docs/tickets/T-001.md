# Ticket T-001: Add `render/` module tree and declare module in `lib.rs` behind `gui` feature

## Objective
Create the new `render/` module tree under `apps/dust-trail/src/render/` and declare it in `lib.rs` behind the `gui` feature flag. This is the foundational ticket that unblocks all other render module work.

## Target Files
- `apps/dust-trail/src/render/mod.rs` (new)
- `apps/dust-trail/src/lib.rs` (modify)

## Acceptance Criteria
- [ ] `apps/dust-trail/src/render/mod.rs` exists and declares submodules: `primitive`, `model`, `raster`, `glyph`, `sprite`, `composite`, `cache`, `camera`
- [ ] `lib.rs` declares `pub mod render` behind `#[cfg(feature = "gui")]`
- [ ] `lib.rs` does NOT declare `tui` module unconditionally (that's T-017)
- [ ] CI passes: `cargo check --all-targets --features gui` (no new warnings)

## Blocking Dependencies
None (this is the first ticket)

## Notes
- Per guide §12.2: new commands and logic go into **new modules** — never edit an existing module to add your feature
- The `render` module is NOT compiled into the domain (no `gui` feature = no render code)
- Keep the module tree flat under `render/`; no nested subdirectories needed
