# Ticket T-009: Extend `Frame` with depth buffer + `set_at_depth`/`depth_at`/`clear_depth`

## Objective
Add a depth buffer to the existing `Frame` type and implement depth-aware write methods.

## Target Files
- `apps/dust-trail/src/domain/frame.rs` (modify existing)

## Acceptance Criteria
- [ ] `Frame` gains a depth buffer: parallel grid of `f32` same dimensions as cells
- [ ] `set_at_depth(x, y, cell, depth)` — overwrites only if `depth` is nearer (smaller) than stored depth at (x, y); updates depth buffer; no-op out of bounds (AC-016)
- [ ] `depth_at(x, y) -> Option<f32>` — returns stored depth at position (AC-016)
- [ ] `clear_depth()` — resets all stored depths to `f32::INFINITY` (AC-017)
- [ ] `set(x, y, cell)` — unchanged flat write semantics (backward compatible)
- [ ] Unit tests: `set_at_depth` near/far behavior, `clear_depth` resets to infinity, out-of-bounds no-op (AC-016, AC-017)
- [ ] CI passes: `cargo test --workspace -- domain::frame` (headless, no GUI)

## Blocking Dependencies
None (can be done in parallel with render module work)

## Notes
- Per spec Section 5: depth does NOT live in `Cell`; depth lives in the `Sprite` grid
- The depth buffer is reset at the start of each frame build
- Per NFR-008: no panic/unwrap in public API — `set_at_depth` never panics out of bounds
- This is in the domain crate, so it's available to both TUI (if it existed) and GUI
