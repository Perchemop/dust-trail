# Ticket T-008: Implement `SpriteCache` (bounded LRU)

## Objective
Implement the bounded LRU cache for rendered sprites, keyed by (model key, light state, size, orientation).

## Target Files
- `apps/dust-trail/src/render/cache.rs` (new)

## Acceptance Criteria
- [ ] `CacheKey` struct with: `model_key: ModelKey`, `light_state: LightState`, `size: (u32, u32)`, `orientation: Orientation`
- [ ] `LightState` quantises light direction + intensity for cache keying
- [ ] `Orientation` enum (fixed in v2.0.0, but keyed for future)
- [ ] `SpriteCache` with methods: `new(max_entries)`, `get(key)`, `insert(key, sprite)`, `len()`, `clear()`
- [ ] Bounded by `max_entries`; on overflow evicts LRU entry (FR-028, FR-031, NFR-005)
- [ ] Same key always returns same sprite (deterministic) (FR-029)
- [ ] Miss returns `None` (FR-030)
- [ ] Unit tests: LRU eviction on overflow, hit returns stored sprite, miss returns None, bounded size (AC-008)
- [ ] CI passes: `cargo test --workspace -- render::cache` (headless, no GUI)

## Blocking Dependencies
- T-006 (Sprite type)

## Notes
- Per NFR-005: memory bound — `SpriteCache` holds at most fixed number of entries; unbounded growth prohibited
- Per NFR-002: cache-hit budget target — 90% cache hit on steady-state repaint
- Per NFR-007: no GUI dependency — `cache.rs` must NOT import egui/eframe
- LRU eviction should be efficient (O(1) get/insert)
