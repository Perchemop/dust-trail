# Ticket T-011: Wire `Game::frame()` to emit sprites + use cache + composite

## Objective
Integrate the new render pipeline into the existing `Game::frame()` method, replacing single-cell emission with sprite-based rendering.

## Target Files
- `apps/dust-trail/src/domain/game.rs` (modify)
- `apps/dust-trail/src/render/` (use from)

## Acceptance Criteria
- [ ] `Game::frame()` builds frame as today (tiles → items → NPCs → player, back-to-front by screen depth)
- [ ] Each object emitted as a `Sprite` instead of single `Cell`:
  - Tiles: single-cell sprites (flat ground) (FR-038)
  - Props/characters: multi-cell sprites from rasteriser (FR-039)
- [ ] Cache integration: `Game` holds `SpriteCache`; reuses cached sprites on repaint (FR-040)
- [ ] Cache invalidation: when world state or light changes, affected entries invalidated (FR-041)
- [ ] Composite: writes each sprite into frame with depth-aware occlusion (uses `composite.rs`)
- [ ] Existing `drawn` Vec of `(sx, sy, Cell)` becomes Vec of sprite placements; final loop calls `set_at_depth` per sprite cell
- [ ] Headless workflow test: move/combat/loot/save loop works through new viewport (FR-046, AC-011)
- [ ] CI passes: `cargo test --workspace -- domain::game` (headless, no GUI)
