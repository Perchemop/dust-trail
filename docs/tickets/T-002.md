# Ticket T-002: Implement `Primitive`, `Transform`, `Material` types

## Objective
Define the core `Primitive` enum and associated types (`Transform`, `Material`) that represent 3D primitives for the rasteriser.

## Target Files
- `apps/dust-trail/src/render/primitive.rs` (new)

## Acceptance Criteria
- [ ] `PrimitiveKind` enum with variants: `Cone`, `Ellipsoid`, `Box`, `Cylinder`, `Capsule`
- [ ] `Primitive` struct with fields: `kind: PrimitiveKind`, `transform: Transform`, `material: Material`
- [ ] `Transform` struct with `translation: (f32, f32, f32)`, `rotation: (f32, f32, f32)`, `scale: (f32, f32, f32)`
- [ ] `Material` struct with `albedo: f32` (0.0..=1.0), `shade_side: bool`
- [ ] No `panic!`, `unwrap`, `expect` in construction — invalid values stored as-is, rasteriser handles degeneracy
- [ ] Unit tests: `Primitive` construction, no panic on invalid values (AC-005)
- [ ] CI passes: `cargo test --workspace -- render::primitive` (headless, no GUI)

## Blocking Dependencies
- T-001 (render module tree exists)

## Notes
- Per spec Section 5: `Primitive` is a plain data type; no panic on construction
- Per NFR-008: no crash discipline — public API functions shall not use panic/unwrap/expect
- Per NFR-009: saturation — all arithmetic derived from input shall use checked/saturating operators
